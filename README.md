# 检测单关联数据抽取（隔离库复现）+ 历史溯源

实验室数据工程师排查样本归属问题时，在网页上选择一张检测单，下载一份**可在空库执行**的
SQL：包含四表结构（主键/外键）以及从该检测单出发、沿外键递归可达的全部被引用行，
用于在隔离库中完整复现问题现场。

新增的**历史溯源**页面用于查清检测单更正前后的归属：启用留痕时保存四表基线，
此后捕获**任何 SQL 连接**对四表的行级增删改；选择检测单与一笔已提交更正，
即可查看该次提交前后的检测单、样本、批次及复测引用路径。

## 快速开始

```bash
docker compose up --build
```

浏览器打开 <http://localhost:8000> ：

- 首页：在检测单列表中点击「下载 SQL」（原导出功能，保持不变）
- <http://localhost:8000/history> ：历史溯源。首次使用点击「启用留痕并保存基线」，
  之后选择检测单即可浏览与其关联数据相关的每笔更正，点击「前后对比」查看详情

- `db`：PostgreSQL 16，首次启动自动建表并写入演示数据（`db/init/*.sql`）；
  数据（含留痕历史）持久化在命名卷 `pgdata`，`docker compose down` 不丢失
  （`down -v` 才会清空）
- `app`：FastAPI + uvicorn，通过 `DATABASE_URL` 连接数据库

## 历史溯源：机制与保证

- **启用即存基线**：「启用」在单个事务内完成——短暂锁定四表
  （`SHARE ROW EXCLUSIVE`，只挡写入不挡读取，拿不到锁 5 秒快速失败）、
  在 `audit` schema 下创建留痕对象、快照四表全部行到 `audit.baseline`。
  任一步失败整体回滚，不留半个启用状态；重复启用只提示、不改写既有历史。
- **行级留痕靠数据库触发器**，对任意连接生效（不经过本应用也照样捕获）：
  - `AFTER ROW` 触发器把每行的改前/改后整行镜像（jsonb）写入
    `audit.row_change`，并按事务号在 `audit.tx` 登记一次——
    **一个事务的多次修改天然归为一笔完整更正**；
  - **可延迟约束触发器**在 COMMIT 时才从序列 `audit.commit_seq` 发放提交序号，
    因此列表顺序就是**实际提交顺序**——先写后提交的事务按提交时刻归位，不会漏；
  - `BEFORE TRUNCATE` 触发器直接报错：TRUNCATE 不产生行级事件，放行会悄悄弄丢历史。
- **同事务原子性**：留痕与源修改同属一个事务——回滚则两者一起消失；
  留痕写入失败（如留痕表被破坏）则源修改随之失败回滚，**不会留下半次更正**。
- **不重不漏的并发语义**：行级锁只作用于被改的行，未提交的长事务不会阻塞
  无关样本的更正；浏览历史只读 `audit.*` 的 MVCC 快照，不阻塞任何写入。
- **历史不可改写**：历史只追加不更新（提交序号在提交瞬间一次性发放）；
  删除后复用编号、后续主档修改、服务重启都不会改写已记录的历史
  （留痕全部存于数据库：触发器与 `audit` 表随数据卷持久化，应用本身无状态）。
- **前后对比如何得出**：从基线出发按提交序号重放行级镜像，重建任一更正
  前后两个时点的四表状态，再按与导出相同的外键可达语义算出该检测单的
  关联闭包（检测单/样本/批次/复测关联链）做行级差异对比；
  **只改关联主档（如批次备注）也会命中**——相关性按当时状态的闭包计算。

## 还原到隔离库

```bash
# 例如还原到本机一个空库 isolated_repro
createdb isolated_repro
psql -v ON_ERROR_STOP=1 -d isolated_repro -f test_order_4_extract.sql
```

脚本在单个事务中执行：建表（仅主键）→ 载入数据 → 统一补外键并校验 → 提交。
任一一步失败整体回滚，不会留下半个库。

## 源库模型（演示数据）

| 表 | 说明 | 演示要点 |
|---|---|---|
| `batches` | 批次 | 含一个无任何样本的空批次 |
| `samples` | 样本 | `batch_id` 为**可空外键**；含无检测单的样本 |
| `test_orders` | 检测单 | 复合外键 `(latest_retest_orig, latest_retest_retest)` → `retest_links`，`DEFERRABLE INITIALLY DEFERRED`；含两列全空、以及**仅一列为空**（悬空值 99）的行 |
| `retest_links` | 复测关联 | **复合主键** `(orig_order_id, retest_order_id)`，两个外键指回 `test_orders`，与 `test_orders` 构成**循环引用** |

## 设计要点

- **同一已提交视图**：导出在单个 `REPEATABLE READ` 只读事务内完成（目录元数据与
  数据行同一快照）；MVCC 快照不持有阻塞锁，抽取期间源端可继续增删改。
- **只追被引用行**：从所选检测单沿“本表 → 被引用表”方向递归（BFS），
  不抓取反向引用（如同一批次的其他样本、同一样本的其他检测单）。
- **复合外键任一列为空即不追查**（与 SQL 外键 MATCH SIMPLE 语义一致）；
  同一行被多次引用时按 `(表, 主键)` 去重，只导出一份。
- **主外键识别自数据库目录**：`information_schema`（表/列/主键/外键，复合外键经
  `position_in_unique_constraint` 配对列）+ `pg_constraint`（可延迟属性），
  不在代码里硬编码表结构。
- **循环引用可完整还原**：生成的脚本与 pg_dump 做法一致——先建表（仅主键）、
  载入数据、最后用 `ALTER TABLE` 补外键并即时校验；全程不关闭约束
  （不使用 `session_replication_role` / `DISABLE TRIGGER`），外键的可延迟属性按源库保留。
- **失败不给部分结果**：SQL 在内存中一次性装配完成才返回附件；读取或生成任一
  环节失败只返回错误页（404/500），不产生部分下载。
- **留痕对象隔离在 `audit` schema**：导出走 `public` schema 目录，不受留痕影响，
  启用留痕后导出内容保持不变。

## 自测

`scripts/selftest.py` 覆盖：首页列表、导出内容断言（无反向引用行、复合外键部分
为空不追查、可空外键为空不追查、去重）、空库还原后行数/外键数量/循环引用数据
校验、外键约束真实生效、脚本幂等重放、404/500 失败路径、REPEATABLE READ 快照
与并发写入不互相阻塞，以及历史溯源端到端：启用与基线行数、重复启用不改写历史、
独立 SQL 连接的行级捕获、一事务多处修改归为一笔、回滚不留痕、先写后提交按实际
提交顺序归位、删除后复用编号的前后对比、只改主档的相关性命中、未提交长事务不
阻塞无关更正、浏览历史不阻塞写入、留痕失败连同源修改回滚、TRUNCATE 拦截、
留痕触发器持久化于数据库目录。历史用例结尾会还原演示数据与留痕对象，
保证自测可重复运行。

```bash
# 依赖：psycopg；可选：psql（提供则用真实 psql 执行还原）
APP_URL=http://127.0.0.1:8000 \
DATABASE_URL=postgresql://lab:lab@127.0.0.1:5432/labdb \
ADMIN_URL=postgresql://lab:lab@127.0.0.1:5432/postgres \
PSQL=$(command -v psql) \
python3 scripts/selftest.py
```

## 已知限制

- 列类型按需求仅支持 `integer` / `text`，遇到其他类型会整体报错（不产生部分结果）。
- 还原目标是隔离复现库：脚本不含序列/自增、索引、视图、触发器；四表之外的
  数据库对象不在抽取范围内。
- 根表固定为 `test_orders`（单列主键），见 `app/extractor.py: ROOT_TABLE`。
- 留痕范围为启用时 `public` schema 的全部基表；启用后新增的表不在留痕范围内。
- 留痕期间四表禁止 TRUNCATE（会产生行级历史空洞）；如确需清空，须先人工
  删除触发器并视为留痕终点。
- 提交序号反映事务进入提交处理的先后（数据库内可获得的实际提交顺序）；
  历史数据只增不减，长期运行需自行归档 `audit.*`。
- 能删表/删触发器的超级用户可绕过留痕，属运维权限边界，不在防护范围。
